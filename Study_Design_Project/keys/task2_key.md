| 1  | **H1 — Visibility of System Status**                                       | Event Detail → sidebar "📅 Add to Calendar" button  | The button has no click handler at all. Clicking it produces no download, no navigation, and no feedback whatsoever — the user cannot tell whether the click succeeded or the feature is broken.                                                | Wire up a real action (download an`.ics` file) with a visible "Added to your calendar" confirmation, or another response that makes the outcome clear.              |
| 2  | **H1 — Visibility of System Status**                                       | Top nav bar on Event Detail and Registration screens | "Browse Events" is highlighted on the listing page, but the highlight disappears the moment the user opens any event, and stays gone through all three registration steps and the confirmation.                                                  | Keep the "Browse Events" highlight active on the event detail and registration pages, and add a breadcrumb (Events › Event › Register) to the registration screens. |
| 3  | **H2 — Match Between System and the Real World**                           | Event Detail → sidebar detail list                  | The capacity row is labeled "Max Occupancy Threshold" — building-code/regulatory jargon that does not match the language used anywhere else in the app.                                                                                        | Relabel in plain language consistent with the rest of the app: "Capacity — 40 attendees" or "Total spots — 40".                                                     |
| 4  | **H3 — User Control and Freedom**                                          | Event Listing → search field and filters            | Searching by keyword or applying a filter, then navigating to another page and back, silently discards the search and filter selections, because the state is never stored anywhere.                                                             | Persist the search and filter state in the URL so it survives navigation and is shareable.                                                                            |
| 5  | **H4 — Consistency and Standards / H8 — Aesthetic and Minimalist Design** | Event Detail → sidebar CTA stack                    | The "Register Now" button is rendered twice, with identical label and styling and no functional difference. Two identical primary buttons break the one-primary-action convention and leave the user wondering whether they do different things. | Remove the duplicate; keep a single "Register Now" followed by the secondary action.                                                                                  |
| 6  | **H5 — Error Prevention**                                                  | My Registrations → "Cancel" button                  | Clicking "Cancel" deletes the registration immediately and permanently, with no confirmation and no undo. One misclick on a list of similar-looking cards irreversibly removes the wrong registration.                                           | Add a confirmation dialog ("Cancel your registration for*Urban Gardening Workshop*?"), or offer a brief "Undo" affordance after canceling.                          |
| 7  | **H5 — Error Prevention**                                                  | Registration Step 1 → input fields                  | The fields carry no input constraints — no`required`, no `pattern`, no `maxlength` — and the phone field accepts arbitrary text. Nothing stops a malformed entry as it is typed; problems surface only after the user clicks "Next".     | Add native`required` / `pattern` / `maxlength` attributes and validate those fields inline, so mistakes are prevented or caught as they are made.               |
| 8  | **H6 — Recognition Rather than Recall**                                    | My Registrations → registration card                | The event title is plain text rather than a link back to the event, and the card omits the information the user submitted. There is no way to re-check what was entered for the registration.                                                    | Link the title to the event detail page and add an expandable "Registration details" section showing the submitted information.                                       |
| ex | **H6 — Recognition Rather than Recall**                                    | Event Listing card + Event Detail sidebar            | After registering, the card still shows "View Details" and the detail page still shows "Register Now" — nothing indicates that the user has already signed up.                                                                                  | Show a "✓ You're registered" badge on the card, and replace the detail CTA with "You're registered — View registration".                                            |
